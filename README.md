# Library API

RESTful API для управления библиотечным каталогом. Позволяет управлять книгами, читателями, а также процессом выдачи и возврата книг.

## Технологии

- **Python 3.12**
- **FastAPI** — веб-фреймворк
- **SQLAlchemy** — ORM для работы с БД
- **SQLite** — база данных
- **Alembic** — миграции БД
- **JWT (python-jose)** — аутентификация
- **passlib[bcrypt]** — хеширование паролей
- **Pydantic** — валидация данных
- **Pytest** — тестирование

## Установка и запуск

```bash
git clone https://github.com/bobifish2929/library-api.git
cd library-api
```

### 2. Создай и активируй виртуальное окружение

```bash
python3 -m venv venv
```


## Как начать работу

### Регистрация первого пользователя (библиотекаря)

```bash
POST /auth/register
{
  "email": "librarian@library.com",
  "password": "yourpassword"
}
```

### Получение токена

```bash
POST /auth/login
username: librarian@library.com
password: yourpassword
```

В ответ придёт `access_token` — его нужно передавать в заголовке всех защищённых запросов:
Authorization: Bearer <ваш_токен>
## Структура базы данных

### Таблица `books`
| Поле | Тип | Описание |
|------|-----|----------|
| id | Integer | Первичный ключ |
| title | String | Название (обязательное) |
| author | String | Автор (обязательное) |
| year | Integer | Год публикации |
| isbn | String | Уникальный ISBN |
| copies | Integer | Количество экземпляров (по умолчанию 1) |
| description | String | Описание |

### Таблица `readers`
| Поле | Тип | Описание |
|------|-----|----------|
| id | Integer | Первичный ключ |
| name | String | Имя (обязательное) |
| email | String | Уникальный email (обязательное) |
| notes | String | Заметки о читателе |

### Таблица `users`
| Поле | Тип | Описание |
|------|-----|----------|
| id | Integer | Первичный ключ |
| email | String | Уникальный email |
| hashed_password | String | Хешированный пароль |

### Таблица `borrowed_books`
| Поле | Тип | Описание |
|------|-----|----------|
| id | Integer | Первичный ключ |
| book_id | Integer | Внешний ключ → books |
| reader_id | Integer | Внешний ключ → readers |
| borrow_date | DateTime | Дата выдачи |
| return_date | DateTime | Дата возврата (NULL если не возвращена) |

## Реализация бизнес-логики

### Бизнес-логика 1: Проверка наличия экземпляров
При выдаче книги проверяем `book.copies > 0`. Если экземпляров нет — возвращаем ошибку 400. При успешной выдаче `copies` уменьшается на 1, при возврате — увеличивается на 1.

### Бизнес-логика 2: Лимит книг на читателя
Перед выдачей считаем количество записей в `borrowed_books` где `reader_id` совпадает и `return_date IS NULL` (книга ещё не возвращена). Если count >= 3 — отказываем.

### Бизнес-логика 3: Проверка при возврате
При возврате ищем запись в `borrowed_books` по `book_id`, `reader_id` и `return_date IS NULL`. Если запись не найдена — значит книга не была выдана этому читателю или уже возвращена.

## Реализация аутентификации

Аутентификация реализована через **JWT (JSON Web Tokens)**:

- При регистрации пароль хешируется через `bcrypt` и сохраняется в БД — сырой пароль никогда не хранится
- При логине проверяем хеш пароля через `passlib`, генерируем JWT токен с помощью `python-jose`
- Токен содержит email пользователя и время истечения (30 минут)
- Защищённые эндпоинты используют `Depends(get_current_user)` — FastAPI автоматически проверяет токен при каждом запросе

### Защищённые эндпоинты
Все эндпоинты кроме `GET /books/` и `POST /auth/register`, `POST /auth/login` требуют токен. Список книг сделан публичным — это удобно для читателей которые хотят узнать есть ли книга в библиотеке без регистрации.

### Библиотеки
- **python-jose** — генерация и проверка JWT токенов
- **passlib[bcrypt]** — надёжное хеширование паролей

## Миграции Alembic

Проект содержит две миграции:
1. `Initial tables` — создание всех таблиц
2. `Add notes field to readers` — добавление поля `notes` в таблицу читателей

## Творческая часть: предлагаемая фича

**Система уведомлений о просроченных книгах**

Можно добавить поле `due_date` (дата когда книгу нужно вернуть) в таблицу `borrowed_books`. Затем реализовать фоновую задачу через `APScheduler` или `Celery`, которая раз в день проверяет просроченные выдачи и отправляет email уведомления читателям через `FastAPI-Mail`. Это сделает систему полезной в реальной библиотеке.
